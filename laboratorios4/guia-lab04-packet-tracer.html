0. Antes de empezar

  • Tenés Cisco Packet Tracer 9.0.1 instalado (C:\Program Files\Cisco Packet Tracer 9.0.1).
  • Guardá temprano: File → Save As… → lab04-aguirre-rangel.pkt. Guardá cada tanto.
  • Se trabaja con un espacio de trabajo (workspace) donde arrastrás dispositivos y los cableás.

Idea central del diseño: la máscara es 255.0.0.0 (/8). Entonces 27.100.0.32, 27.200.0.53 y 27.1.0.2 están todos en la misma red 27.0.0.0/8. Por eso no hay router y el DNS 27.1.0.2 sirve a las 3 sedes. Todo se ve con cableado directo y switches.

1. Montar la topología

1.1 Colocar los dispositivos

En el panel inferior izquierdo están las categorías. Hacé clic y arrastrá al área de trabajo:

  1. Network Devices → Switches → 2950-24 (arrastrá 3).
  2. End Devices → PC (arrastrá 5: S1, S2, C1, C2, E1, E2 → en realidad 6).
  3. End Devices → Server (arrastrá 6: www.sistemas, mail.sistemas, DNS, www.civil, mail.civil, mail.electrica).

Renombrá cada equipo: clic sobre el nombre debajo del ícono, o seleccioná el equipo → pestaña Config → Global Settings → Display Name.

1.2 Cablear

  1. Elegí Connections (el ícono del rayo) → Copper Straight-Through (cable directo).
  2. Primero clic en el dispositivo → elegí la interfaz (en PC/Server: FastEthernet0; en switch: FastEthernet0/1, 0/2…).
  3. Clic en el otro dispositivo → su interfaz.

Esquema de conexiones (estrella):

Cada PC/Server  -> a un puerto libre de SU switch          (cable directo)
Switch0 (sistemas) -> Switch1 (civil)    en un puerto libre (cable directo)
Switch0 (sistemas) -> Switch2 (electric) en un puerto libre (cable directo)

Los switches 2950 ya funcionan de fábrica (no hay que configurarlos para esta topología). Un cable directo alcanza porque los switches modernos tienen auto-MDIX. Podés ver los puertos usados abriendo el switch → pestaña Config, o pasar el mouse por el cable.

2. Direccionamiento

2.1 Cómo cargar la IP en una PC o Server

  1. Clic en la PC/Server → pestaña Desktop → IP Configuration.
  2. Elegí Static (estático) y completá: IPv4 Address, Subnet Mask, Default Gateway, DNS Server.
  3. Cerrá la ventana (se aplica solo).

Alternativa: pestaña Config → Settings (mismos campos) o Config → Global Settings para el nombre.

3. Configurar los servicios

Todos los servicios se configuran abriendo el Server → pestaña Services. A la izquierda elegís el servicio (DNS, HTTP, …) y a la derecha lo configurás. Después guardás con el botón del servicio (Save / Add / Start según corresponda).

3.1 DNS — en el Server 27.1.0.2

  1. Server DNS → Services → DNS.
  2. En DNS Service: On (Service). En Name poné el nombre, en Type elegí A Record o CNAME, en Address poné la IP (para A) o el nombre destino (para CNAME). Add.

3.2 HTTP — en 27.100.0.32 y 27.200.0.53

  1. Server → Services → HTTP → On.
  2. En la lista de archivos elegí index.html → botón Edit (se abre un editor). Cambiá el contenido para personalizarlo por facultad (p. ej. "Bienvenido a Sistemas" / "Bienvenido a Civil"). Guardá con Save.
  3. Opcional: agregá otra página (por ejemplo prueba.txt) para probar descargas.

3.3 Email — en 27.100.0.33, 27.200.0.52, 27.150.0.102

  1. Mail server → Services → Email → On.
  2. Domain name: sistemas.com (o civil.com / electrica.com según el server).
  3. En User Setup: User = nombre del cliente (p. ej. StudentS1), Password = la que quieras → Add. Repetí por cada usuario de esa facultad.
  4. En cada PC: Desktop → Email → completá:
    • Your Name: Student S1
    • Email Address: students1@sistemas.com
    • Incoming Mail Server: pop3.sistemas.com
    • Outgoing Mail Server: smtp.sistemas.com
    • User Name / Password: los del paso 3
    → Save.
  5. Para enviar: Compose → To: el correo del otro → Subject/Body → Send. Luego Receive (icono del sobre) para bajar los correos nuevos.

3.4 FTP — en el web server de sistemas (27.100.0.32)

  1. Server → Services → FTP → On.
  2. En User Setup: Username = tu nombre (p. ej. camilo), Password = tu apellido (aguirre) → marcá todos los permisos → Add.
  3. Asegurate de que en la lista de archivos haya alguno para descargar (los que ya trae Packet Tracer sirven).

Los permisos del FTP (ojo con esto)

LetraPermisoQué habilita
RReadget (descargar)
WWriteput (subir)
DDeleteborrar archivos
NRenamerenombrar archivos
LListdir (listar el directorio)

Error típico: si el usuario no tiene L, el dir da "permission denied" y el get falla con "file not found" — aunque el archivo exista. Solución: tildá List (dejá R, W, D, N, L todos marcados).

Ojo: Packet Tracer no tiene un botón para "agregar" archivos al FTP. Los que aparecen ya vienen puestos. Para agregar uno propio, se sube desde el cliente con put.

4. Probar

4.1 Ping por nombre

En un cliente de cada sede: Desktop → Command Prompt:

ping sistemas.com
ping mail.sistemas.com
ping www.civil.com
ping electrica.com

Si resuelve el nombre y responde → el DNS funciona. (La primera respuesta puede ser Request timed out por ARP; las siguientes responden.)

4.2 HTTP por IP y por URL

En una PC: Desktop → Web Browser. Probá:

http://27.100.0.32          (por IP)
http://www.sistemas.com     (por URL -> usa DNS)
http://http.civil.com       (por URL)

Tenés que ver la página que personalizaste. Por IP y por URL deben dar lo mismo.

4.3 Correo dentro y entre dominios

  • Dentro: S1 → S2 (ambos @sistemas.com).
  • Entre dominios: S1 → C1 (@sistemas.com → @civil.com).
  • Responder el correo recibido y verificar que llega.

4.4 FTP: descargar y subir

Desde el Command Prompt de una PC:

ftp 27.100.0.32      (conecta al FTP)
camilo               (usuario)
aguirre              (password)
ls                   (lista archivos)
get datos.txt        (descarga)
quit                 (sale)

Verificá que el archivo quedó en la PC (abrí Desktop o usá otros comandos del prompt).

4.5 DNS: consultar directo

nslookup www.sistemas.com
nslookup pop3.civil.com

Te muestra el servidor DNS usado y el resultado. Con CNAME vas a ver la cadena alias → destino.

5. Modo Simulation: ver los PDU

  1. Abajo a la derecha, cambiá de Realtime a Simulation.
  2. Show All/None o el filtro por protocolo: dejá solo DNS, HTTP, SMTP, POP3, FTP, TCP, UDP… según lo que quieras ver.
  3. En la barra lateral, elegí Add Simple PDU (el sobre cerrado), hacé clic en el origen y luego en el destino (o usá Capture/Forward para avanzar el tráfico generado por una acción real).
  4. En el Panel de simulación (abajo) aparece la lista de eventos. Hacé clic en un evento y mirá el recuadro de la derecha:
    • PDU Information → mirá las capas (OSI Model): en Application ves el mensaje (p. ej. la petición HTTP, o el diálogo SMTP/POP3), y en Transport ves los puertos (HTTP 80, DNS 53, SMTP 25, POP3 110, FTP 21/20).
    • Inbound/Outbound PDU Details → el contenido literal del mensaje (headers + datos).

6. Comandos explicados (con parámetros)

6.1 Command Prompt de la PC (Packet Tracer)

Se abre en PC → Desktop → Command Prompt. Es una consola tipo Windows.

ipconfig — ver/renovar la IP

ComandoQué hace
ipconfigMuestra IP, máscara y gateway.
ipconfig /allAdemás: MAC, DNS, DHCP…
ipconfig /releaseLibera la IP (la "devuelve").
ipconfig /renewPide IP nueva.

ping — ¿hay conectividad?

ping <destino>            ping 27.100.0.33   /  ping sistemas.com
ping <destino> -n <n>      manda n paquetes (ej. -n 5)
ping <destino> -t          no para hasta Ctrl+C
ping <destino> -l <tam>    tamaño del paquete en bytes (ej. -l 1000)

Usa ICMP. "Reply from…" = OK. "Destination host unreachable" = no hay ruta (revisá IP/cable). "Request timed out" = no responde (¿firewall? ¿host apagado?).

tracert — ver el camino

tracert <destino>         tracert www.civil.com

Muestra los "saltos" (routers) hasta el destino. Acá, como es una sola red, debería salir directo.

nslookup — consultar el DNS

nslookup <nombre>         nslookup www.sistemas.com
nslookup <nombre> <server>  nslookup civil.com 27.1.0.2

Sin el segundo parámetro usa el DNS configurado. Devuelve el nombre → IP (o la cadena CNAME).

arp — tabla de direcciones MAC

arp -a                    muestra IP -> MAC conocidas

ftp — transferencia de archivos

ftp <servidor>            ftp 27.100.0.32
  <usuario>                 camilo
  <password>                aguirre
  dir                       lista los archivos (¡NO es "ls"!)
  get <archivo>             descarga (baja)
  put <archivo>             sube
  quit                      cierra la sesión

get = descargar; put = subir. FTP usa los puertos 21 (control) y 20 (datos).

En Packet Tracer el listado es dir, no ls (ls responde "Invalid or non supported command"). Y para que dir y get funcionen, el usuario necesita los permisos L y R (ver 3.4).

telnet — conexión de texto a un puerto

telnet <host> [puerto]    telnet 27.100.0.32 80

Sirve para "hablar" HTTP a mano: al conectar al puerto 80 escribís GET /index.html y ves la respuesta cruda. (La guía lo menciona para el FTP; en PT lo normal es el ftp.)

Se abre en Switch → CLI. Arranca en Switch> (modo usuario).

Los 2950 son switch de capa 2: no llevan IP en los puertos. Su trabajo es reenviar por MAC; por eso para esta topología no hace falta configurarlos.

7. Errores comunes y entregable

Errores comunes

SíntomaCausa típica
No resuelve el nombre (Request timed out al ping por nombre)Falta el registro DNS, o la PC no tiene el DNS 27.1.0.2 configurado.
No ping de una sede a otraFalta el cable entre switches, o una IP/máscara mal cargada.
La web no abre por URL pero sí por IPEl DNS no tiene el registro http.… o el www.
El correo no llegaUsuario/clave mal en el cliente, o dominio del server distinto.
FTP no logueaUsuario sin permiso (R/W), o contraseña distinta.

Entregable

  • El archivo .pkt con la red armada y probada.
  • Documento con capturas: topología, IP de cada dispositivo, registros DNS, servicios activos, pruebas (ping por nombre, web por IP y URL, correo dentro/entre dominios, FTP get/put) y las PDU en modo Simulation.
  • Cada estudiante configura la red y documenta la experiencia (dice la guía).
