Base: las 5 piezas que usan los 3 scripts

Antes de tocar un script, entendé estas piezas. Son las mismas en los tres.

1. Shebang y ejecución

1#!/bin/sh

La primera línea le dice al sistema qué intérprete usar. #!/bin/sh = shell POSIX (funciona en Solaris Y Slackware). Para ejecutar: chmod +x script.sh y después ./script.sh. Sin el ./, el shell no busca en el directorio actual.

2. Parámetros y defaults: ${1:-valor}

1NUM="${1:-10}"   # parámetro 1, o "10" si no lo pasaron

$1, $2, $3 son los parámetros de la línea de comandos. La forma ${1:-default} significa: "si el parámetro 1 existe y no está vacío, úsalo; si no, usá default". Así el script funciona con o sin argumentos.

Ejemplo: ./files-script.sh usa NUM=10; ./files-script.sh 5 2MB usa NUM=5.

3. Sustitución de comando: $( ... )

1CAMPOS=$(echo "$FREC" | awk '{print NF}')

Todo lo que está dentro de $( ... ) se ejecuta primero y su salida se guarda en la variable. Es como llamar a una función: la variable queda con el resultado del comando.

4. Pipes: | (tuberías)

1comando1 | comando2 | comando3

El pipe conecta la salida de un comando con la entrada del siguiente. Es el superpoder de UNIX: comando chico hace una cosa, y encadenás varios. Los pipes son la forma de pensar "transformaciones en serie": find produce → sort ordena → head recorta → awk formatea.

5. Redirección: >, 2>

1crontab -l 2>/dev/null   # manda los errores a la basura
2/bin/date >> /tmp/x.log   # agrega al final (>>), no pisa (>)

> pisa el archivo, >> agrega al final. 2> redirige la salida de errores (stdin=0, stdout=1, stderr=2). /dev/null es el "tacho de basura" del sistema.

Script 1 · schedult-task-script.sh — tareas periódicas

Problema: programar un comando para que el sistema lo ejecute solo, cada cierto tiempo. Lo resuelve cron: un demonio que lee una tabla por usuario (crontab) y ejecuta lo que encuentra.

Cron: los 5 campos

CampoRangoSignificado
1º minuto0-59En qué minuto de la hora
2º hora0-23En qué hora del día
3º día del mes1-31Qué día del mes
4º mes1-12En qué mes
5º día de semana0-7Qué día (0 o 7 = domingo)

* = "todos". * * * * * = cada minuto. */5 * * * * = cada 5 minutos. 0 3 * * 1 = lunes a las 3:00 AM.

Simulador de cron

Completa los 5 campos y mirá cuándo se ejecutaría tu tarea hoy. Probá: * * * * *, */10 * * * *, 30 8 * * 1.

Desglose línea por línea — clickeá cada línea del código

1#!/bin/sh
2# schedult-task-script.sh [frecuencia] [tarea]
3
4FREC="${1:-* * * * *}"
5TAREA="${2:-/bin/date >> /tmp/schedult-task.log}"
6
7CAMPOS=$(echo "$FREC" | awk '{print NF}')
8if [ "$CAMPOS" -ne 5 ]; then
9    echo "Frecuencia invalida..."
10    exit 1
11fi
12
13( crontab -l 2>/dev/null | grep -v -F "$TAREA"; echo "$FREC $TAREA" ) | crontab -
14
15echo "Tarea programada:"
16echo "  $FREC $TAREA"
17echo ""
18echo "Crontab actual:"
19crontab -l

Hacé click en una línea del código para ver su explicación.

La línea estrella (línea 13), desarmada

crontab -l lista la tabla actual → grep -v -F "$TAREA" elimina líneas que ya contengan la tarea (evita duplicados; -v = invertir, -F = texto fijo, no regex) → echo "$FREC $TAREA" agrega la tarea nueva. Todo dentro de ( ... ) (subshell) se junta y se pipa a crontab -, que reemplaza la tabla desde stdin. Patrón clásico: leer → filtrar → escribir.

Script 2 · menu-procesos.sh — administración de procesos

Problema: un menú interactivo para administrar procesos sin memorizar comandos. Estructura: loop infinito + read + case — el patrón de TODO menú en shell.

La estructura: while + case

1while true; do
2    echo "1) Listar procesos"
3    read OPC          # espera que el usuario escriba
4    case "$OPC" in    # despachador: decide según lo escrito
5        1) ... ;;
6        5) exit 0 ;;  # salir del script
7        *) echo "Opcion invalida." ;;
8    esac
9done

read bloquea esperando input. case ... esac compara y ejecuta. * es el caso "cualquier otra cosa". done cierra el loop → vuelve a mostrar el menú. Sin exit 0, el menú nunca termina: eso es lo que querés en un menú.

Los 4 comandos de procesos que tenés que conocer

ComandoQué haceEn el script
ps -eo comm,pid,%mem,%cpuLista procesos con columnas personalizadas (-o = formato propio, -e = todos)opción 1 y 2
kill <PID>Manda señal 15 (SIGTERM): "pedido de cortesía" para terminaropción 3
pgrep -x nombreBusca el PID de un proceso con nombre exacto (-x)opción 4
ps -p PID -o args=Devuelve la línea de comando completa de un PIDopción 4
El truco grep -v grep: cuando buscás procesos con ps | grep nombre, el propio grep aparece en la lista. grep -v grep lo filtra. Lo vas a ver en TODOS los scripts de la vida real.

Reiniciar = matar y relanzar

1CMD=$(ps -p "$PID" -o args=)   # 1. guardar el comando
2kill "$PID"                     # 2. matar
3sleep 1                         # 3. esperar a que suelte recursos
4sh -c "$CMD" >/dev/null 2>&1 &  # 4. relanzar en background (&)

No existe un comando "reiniciar proceso": es kill + relanzar. Se lanza con & al final para que corra en background y no bloquee el menú. Si no sos root, el script te avisa que uses service nombre restart.

Código completo — clickeá las líneas

1#!/bin/sh
2# menu-procesos.sh
3while true; do
4    echo ""
5    echo "===== ADMINISTRACION DE PROCESOS ====="
6    echo "1) Listar procesos (nombre, PID, %mem, %cpu)"
7    echo "2) Buscar proceso por nombre"
8    echo "3) Matar proceso"
9    echo "4) Reiniciar proceso"
10    echo "5) Salir"
11    echo -n "Opcion: "
12    read OPC
13    case "$OPC" in
14        1)
15            ps -eo comm,pid,%mem,%cpu --sort=-%mem | head -n 20
16            ;;
17        2)
18            echo -n "Nombre del proceso: "
19            read NOMBRE
20            ps -eo pid,comm,%mem,%cpu,args | grep -i "$NOMBRE" | grep -v grep
21            ;;
22        3)
23            echo -n "PID a matar: "
24            read PID
25            kill "$PID" && echo "Proceso $PID terminado." || echo "No se pudo terminar $PID."
26            ;;
27        4)
28            echo -n "Nombre del proceso a reiniciar: "
29            read NOMBRE
30            PID=$(pgrep -x "$NOMBRE" | head -n 1)
31            if [ -z "$PID" ]; then
32                echo "Proceso '$NOMBRE' no esta en ejecucion."
33            else
34                CMD=$(ps -p "$PID" -o args=)
35                kill "$PID" && echo "Proceso $PID terminado."
36                sleep 1
37                if [ "$(whoami)" = "root" ]; then
38                    case "$CMD" in
39                        *" "* | *"/"*) sh -c "$CMD" >/dev/null 2>&1 & echo "Reiniciado: $CMD" ;;
40                        *) "$CMD" >/dev/null 2>&1 & echo "Reiniciado: $CMD" ;;
41                    esac
42                else
43                    echo "Reinicio manual (requiere privilegios): service $NOMBRE restart"
44                fi
45            fi
46            ;;
47        5)
48            echo "Saliendo..."
49            exit 0
50            ;;
51        *)
52            echo "Opcion invalida."
53            ;;
54    esac
55done

Script 3 · files-script.sh — recorrido del filesystem

Problema: recorrer un árbol de directorios y mostrar los N archivos más pequeños menores a un tamaño máximo.

La conversión de unidades (líneas 9-11): la joya del script

1UNI=1; case "$MAX" in *GB) UNI=1073741824;; *MB) UNI=1048576;; *KB) UNI=1024;; esac
2MAXB=$(( ${MAX%[GMK]B} * UNI ))

$(( ... )) = aritmética del shell. ${MAX%[GMK]B} = recorte de sufijo: % recorta desde el final la parte que calce con el patrón [GMK]B (una letra G, M o K seguida de B). 1GB → 1 → 1 × 1073741824 bytes. Un case que convierte y una línea de aritmética: unidad lista.

El find con tamaño en bytes

1find "$DIR" -type f -size -"$MAXB"c -printf '%s %p\n'

find recorre recursivamente. -type f = solo archivos (no carpetas). -size -Nc = menores a N bytes (la c después del número le dice a find "esto está en bytes"). -printf '%s %p\n' = imprime tamaño (%s) y ruta (%p). El 2>/dev/null silencia errores de permisos en carpetas que no podés leer.

Si omitís la c, find interpreta el tamaño en bloques de 512 bytes — un clásico error que confunde a todos.

La pipa final: producir → ordenar → recortar → formatear

1find ... | sort -n | head -n "$NUM" | awk '{ ... }'

sort -n = orden numérico (si no, "10" iría antes que "9"). head -n N = quedarse con los primeros N → como ya está ordenado de menor a mayor, son los N más chicos. awk formatea: separa nombre de ruta con sub().

Código completo — clickeá las líneas

1#!/bin/sh
2# files-script.sh [no_files] [max_size] [dir]
3NUM="${1:-10}"; MAX="$2"; DIR="${3:-.}"
4
5[ -z "$MAX" ] && { echo "Uso: $0 [no_files] [max_size] [dir] (ej: $0 10 1GB)"; exit 1; }
6
7# Convierte 1GB/100MB/50KB a bytes (1 linea en vez de un case por sufijo)
8UNI=1; case "$MAX" in *GB) UNI=1073741824;; *MB) UNI=1048576;; *KB) UNI=1024;; esac
9MAXB=$(( ${MAX%[GMK]B} * UNI ))
10
11echo "Los $NUM archivos mas pequenos (< $MAX) en $DIR:"
12find "$DIR" -type f -size -"$MAXB"c -printf '%s %p\n' 2>/dev/null \
13 | sort -n | head -n "$NUM" \
14 | awk '{ n=$2; sub(/.*\//,"",n); d=$2; sub(/\/[^/]*$/,"",d); print n" -> "d" ("$1" bytes)" }'

El -z y el && de la línea 5

[ -z "$MAX" ] = "¿la variable está vacía?" (-z = zero-length). Si está vacía, ejecuta { ...; exit 1; } — muestro el uso y salgo con código de error 1. El && significa "solo ejecutá lo de la derecha si lo de la izquierda fue exitoso". Validar entrada antes de trabajar = la diferencia entre script profesional y script de juguete.

Portabilidad: Solaris vs Slackware (lo que te destaca)

La guía exige que los scripts corran en Solaris Y Slackware. Slackware usa herramientas GNU (procps, GNU findutils); Solaris usa las suyas. Hay 3 construcciones que funcionan en Slackware y fallan en Solaris:

ConstrucciónScriptPor qué falla en SolarisAlternativa portable
GNUps --sort=-%mem Menú, opción 1 --sort es extensión de GNU ps; el ps de Solaris no lo acepta ps -eo comm,pid,pcpu,pmem | sort -k4 -rn
GNU%mem / %cpu Menú, opciones 1-2 En Solaris el keyword es pcpu / pmem Usar pcpu,pmem — GNU ps también los acepta, así que funcionan en ambos
GNUfind -printf files-script -printf es extensión GNU; el find de Solaris no la tiene find ... -exec ls -l {} \; o -exec wc -c {} \; + procesar
Receta: ps con keywords pcpu,pmem corre en ambas máquinas. Para ordenar, usá sort -k4 -rn (cuarta columna, numérica, reversa). Para find, evitá -printf. Así un solo script sirve para los dos servidores — que es exactamente lo que pide la guía.
