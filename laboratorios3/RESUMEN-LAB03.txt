1.3 PASOS DE INSTALACION Y CONFIGURACION (ejemplo en Slackware)
---------------------------------------------------------------
1. Instalar el paquete DNS (BIND) desde el CD/ISO si hace falta:
     mount /dev/cdrom /mnt/cdrom
     cd /mnt/cdrom/slackwareX.X
     installpkg bindX.X.txz
     umount /mnt/cdrom
2. Verificar que los paquetes quedaron instalados (en Slackware usar pkgtools).
3. Configurar el servicio:
   a) /etc/named.conf
      - options { directory "/etc/DNS"; };
      - zona raiz (hint) "." con archivo named.ca (resolucion de dominios
        externos).
      - zona del dominio propio: type master; file "mi_dominio.hosts".
      - la zona reversa (127.0.0) NO se configura en este lab (opcional).
   b) /etc/DNS/named.ca  -> lista de servidores raiz. Empezar con uno,
      probar y luego agregar al menos dos mas (con registros A y AAAA).
   c) /etc/DNS/mi_dominio.hosts -> registros:
      - $INCLUDE named.soa (o escribir el SOA directo)
      - registro NS del servidor (dns.mi_dominio.)
      - MX comentado (no se usa en este lab)
      - localhost.mi_dominio. IN A 127.0.0.1
      - this_server.mi_dominio. IN A <ip del servidor DNS>
      - real_name_1.mi_dominio. IN A <ip servidor 1>
      - real_name_2.mi_dominio. IN A <ip servidor 2>
      - alias_1.mi_dominio.  IN CNAME real_name_1.mi_dominio.
      - alias_2.mi_dominio.  IN CNAME real_name_2.mi_dominio.
      - (IPv6: revisar como configurar los registros AAAA)
   d) /etc/DNS/named.soa -> SOA:
      @ IN SOA this_server.mi_dominio. root.mi_dominio. ( serial )
      Serial: formato yyyyMMddxx (consecutivo del dia).
4. Arrancar el servicio:  /usr/sbin/named start

PARTE 2 — COMANDOS UTILES (PROGRAMACION SHELL)
--------------------------------------------------------------------------------
Escribir programas Shell para los servidores Solaris y Linux Slackware:

(a) PROGRAMACION DE TAREAS PERIODICAS
    Script que permite configurar una tarea para que se ejecute
    periodicamente. El usuario especifica la tarea y su frecuencia POR LINEA
    DE COMANDOS (NO se piden parametros interactivamente). Ejemplos:
      solaris# ./schedult-task-script.sh [frecuencia]
      solaris# ./schedult-task-script.sh * * * * *
    (equivale a programar cron segun la frecuencia dada)

(b) SHELL CON MENU DE OPCIONES
    Menu con una opcion para salir; las otras ejecutan un comando y
    vuelven al menu. Debe permitir:
      - Mostrar los procesos en ejecucion del servidor con: nombre del
        proceso, identificador (PID), % de uso de memoria y % de uso de CPU.
      - Buscar un proceso dado por el usuario y mostrar su informacion
        completa.
      - Matar/cerrar un proceso en ejecucion.
      - Reiniciar un proceso en ejecucion.

(c) RECORRIDO DEL SISTEMA DE ARCHIVOS
    Script que recorre el sistema de archivos desde un directorio dado,
    incluyendo subdirectorios, y muestra los n archivos mas pequenos dentro
    de un tamano especificado por el usuario. La salida debe indicar:
    nombre del archivo, ruta donde se encuentra y tamano. Ejemplos:
      slackware# ./files-script.sh [no_files] [max_size]
      slackware# ./files-script.sh 10 1GB

NOTAS:
- Para grupos de 3: los puntos (b) y (c) tambien en PowerShell en Windows
  Server. Grupo de 1: Shell para Solaris. (Grupo de 2: Shell para Solaris
  y Slackware, sin PowerShell.)

3.2 LANZAR UNA INSTANCIA (paso a paso segun la guia)
----------------------------------------------------
1. Abrir la consola de EC2.
2. Seleccionar la Region (usar la actual u otra mas cercana).
3. Launch instance desde el dashboard.
4. Nombre descriptivo para la instancia.
5. Application and OS Images: Quick Start, Amazon Linux recomendado,
   elegir AMI con Free Tier eligible.
6. Instance type: elegir tipo Free Tier eligible.
7. Key pair: crear nueva o usar existente.
8. Network settings: VPC y subnet default. Security group debe permitir
   SSH (Linux) o RDP (Windows). Para el primer intento usar defaults.
9. Configure storage: root volume (suficiente para pruebas).
10. Revisar el resumen y Launch instance.
11. Ir a la pagina Instances y monitorear el estado: pending -> running.
12. Cuando pase los status checks, esta lista para conexiones.

3.3 CONECTARSE A LA INSTANCIA
-----------------------------
- Desde Windows: abrir terminal y usar el comando ssh (OpenSSH).
- En la consola: Instances -> seleccionar -> Connect -> pestaña SSH client.
- Copiar el comando de ejemplo:
    ssh -i key-pair-name.pem ec2-user@ec2-198-51-100-1.us-east-2.compute.amazonaws.com
- Si el .pem no esta en el directorio actual, usar ruta completa.
- Verificar el fingerprint (Actions -> Monitor and troubleshoot -> Get
  system log) para evitar man-in-the-middle.
- Responder yes a la autenticidad del host.
